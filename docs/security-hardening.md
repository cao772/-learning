# yanhaoo.com｜生产安全收口与实施边界

适用范围：腾讯云北京轻量应用服务器（Ubuntu 24.04，2 核 2 GB），域名 `yanhaoo.com` 已提交 ICP 备案申请，但 **未核实审核通过**。本文件是交付工具和操作流程，**不是实际服务器已加固的证据**。

## 1. 安全检查（无副作用）

在已获授权的服务器 SSH 终端运行 `bash deploy/host-security-audit.sh`。脚本只读，核实：

- TCP 监听地址：试运行网站应只监听 `127.0.0.1:8788`，不可出现 `0.0.0.0:8788`。
- SSH：使用密钥登陆，核验有效 `sshd -T` 的 `permitrootlogin` 和 `passwordauthentication`；没有备用可用会话之前 **不要禁用现有登陆方式**。
- UFW 或 nftables/firewalld：检验入站规则；同时核查**腾讯云轻量服务器防火墙**的安全策略（云防火墙与系统 UFW 是两层控制）。
- Docker 端口发布：Docker 映射端口可能绕过 UFW 的 FORWARD 预期；生产 Compose 的 hub 不发布宿主机端口，Caddy 只在备案且 HTTPS 可用后开放 80/443。
- `apt list --upgradable`、自动安全更新、磁盘剩余空间；更新前需要留备份、可用 SSH 备用连接和回滚路径。

> 审计输出仅存受控位置。脚本不能检查腾讯云后台安全组，也不对外发送日志。

## 2. 备案审核期间推荐安全基线

- 腾讯云服务器防火墙：仅按需允许 SSH 端口（最好限制来源 IP，前提是可固定），暂不开放 80/443。关闭不需要的管理端口、数据库端口和 Docker API。
- 操作系统防火墙：核对实际 SSH 端口和备用连接后，以 `sudo ufw allow <SSH端口>/tcp` + `sudo ufw default deny incoming` 为起点；**任何 `sudo ufw enable` 前必须验证可恢复的远程访问、已添加 SSH 允许规则**。如 UFW 规则由厂商/其他程序管理，禁止盲目重置。
- SSH：先验证非 root 密钥账户和 `sudo`，再在独立 SSH 连接中测试。最后才考虑禁用口令、root 远程登录；修改前运行 `sudo sshd -t`，更新后复测两个会话。
- 服务器保持试运行的回环映射 + SSH 隧道；个人笔记与管理 API 的匿名拒绝结果必须持续为 401/302。
- 登陆限流按来源 IP 计数。正式 Caddy 的单层代理模式显式设置 `HUB_TRUST_PROXY=1`，SSH 隧道直连预览覆盖为 `0`；如果引入多级 CDN/代理，必须重新审查可信代理跳数与来源 IP 伪造问题。
- 更新先执行 `apt-get -s upgrade` 模拟；需要重启时安排维护窗口。**不得直接升级 Docker 主版本或覆写业务镜像**。
- 不要把 SSH 密钥、令牌、数据库、用户数据、截图放进公开 GitHub PR 或 CI logs。

## 3. 备案实际通过后再转生产

1. 在腾讯云备案控制台核实完成状态/备案号，确认适用的公网部署要求。
2. 备份现有 SQLite 数据，验证备份文件完整性；记录当前镜像 SHA 与回滚路径。
3. 云端安全组放通 80/443，系统防火墙相应放通；仅在容器 Caddy 实际准备就绪后发布服务。
4. 配置 `yanhaoo.com` A 记录到服务器 IPv4，核实真实 DNS 传播。启用 Caddy 正式 HTTPS，关闭试运行覆盖文件 `compose.preflight.yaml` 并恢复 `HUB_SECURE=1`。
5. 通过公网浏览器验收：匿名首页/精选/候选/46 课可访问，站主私有 API 与笔记不可匿名读取；表单写入需要 CSRF。确认 HTTP 重定向到 HTTPS 且证书有效。
6. 根据适用要求完成公安联网备案及页面标识。

## 4. 备份、告警与恢复

- 当前是同机每日一致性 SQLite 备份，保留 14 个快照；已有一次下载到本机的副本，**尚无自动异地备份**。
- 下一阶段可利用已授权 SSH/SFTP，把每日新备份**加密**存到独立位置，每天校验校验和，并每月至少一次隔离恢复；不要用公开对象存储桶备份私人笔记。
- 已增加可选 `deploy/download-encrypted-backup.sh`，从现有 SSH + `hub.offsite_stream` 获取**经 SQLite integrity_check 验证**的在线快照，并在本地立即用 `age` 公钥加密为 `.sqlite.age`。此工具尚**未在真实云主机上执行**，不是已启用的自动异地备份。输入环境变量为 `YH_BACKUP_SSH_TARGET`、`YH_BACKUP_SSH_KEY`、`YH_BACKUP_KNOWN_HOSTS`、`YH_BACKUP_DIR`（必须在受控 `.private` 目录内）及 `YH_AGE_RECIPIENT`（仅公钥）。用户应离线保管私钥，不能写进服务器或代码仓库。首次运行后，在隔离环境执行 `age -d -i <私钥文件> <快照.age> > <临时文件.sqlite>` 并检查完整性/笔记，随后安全清理临时明文文件；通过测试才能启用定时运行。
- 监控备份容器是否 healthy、备份最新时间、磁盘使用率、错误日志、Caddy 证书续期。阈值告警需由用户指定通知渠道，未指定前只收集到本地/受控日志。
- 告警推荐：磁盘占用超过 80%、备份超过 26 小时、hub 变为 unhealthy、同步失败持续超过 15 分钟（macOS 睡眠期间应标注为数据源离线，不等于云端故障）。
- 执行恢复前先停写、保留原数据库；只在隔离库验证成功后考虑生产回滚。

## 5. 本轮已落实的代码级优化

- 公开页提供客户端搜索、核验状态过滤与数据最近入库时间，保留原有服务端渲染和无需 JS 的可读性。
- Flask 响应增加 `object-src 'none'`、`Permissions-Policy` 与同源资源/窗口策略；不改变现有课程离线 HTML。
- 测试补充公共查询页面与安全头回归；已加入静态 JS 语法和 shell 脚本语法 CI 检查。
