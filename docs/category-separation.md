# 循序 learning｜内容分类独立展示（V3）

本轮按用户明确纠正：**Agent、论文、开源工具不是同一种类别，不能放在一个未区分的内容列表里**。

## 页面结构

私人「兴趣发现 → 为我发现」提供独立主分类栏目：Agent 与智能体、论文与科研、开源工具与代码项目、产品与应用、教程与实践、架构与工程、跨学科探索、行业动态与观点、待分类。全部分类视图按栏目分段呈现；点击任一分类只展示此类内容。统计为当前排名结果中的条数，不代表源站全量。

与过去的“兴趣权重”不同，**主分类是内容呈现方式，兴趣是可交叉匹配的技术标签**，二者保留为两个维度。

例如：
- 标题含 Agent，源为原始论文 arXiv：主分类 **论文与科研**；技术标签可为「Agent」。
- 标题含 MCP、GitHub 代码仓库链接：主分类 **开源工具与代码项目**；技术标签可为「Agent」。Github 仓库并不证明是开放许可，必须核实许可证后才能正式断言开源。
- Agent Harness 经验文章，无论文或代码仓库原文链接：主分类 **Agent 与智能体**。
- GitHub Trending 页面或博客只提及 GitHub：不能据此认定是代码仓库，信息不足的条目保留待分类。

**每条内容只有一个主分类**，避免 Agent/论文/开源项目被当成相同内容类型或重复计数。分类引擎只基于当前项目已经接收的标题/URL/已有元数据，提供“归类依据”与“待核验”说明，不调用外部模型、不查询 GitHub stars、不会把候选自动升级精选。

## 实际代码

- `hub/content_category.py`：保守规则、9 个互斥主分类及相关标签。
- `hub/app.py`：站主 `/api/discover` 的每条 `ranking` 增加 `category/category_label/category_reason/topic_tags`，另提供 `categories` 计数；私人手工收藏条目也增加分类显示，不影响旧数据库结构。
- `hub/static/discovery-ui.js`：首屏按主分类分段；筛选条切换 Agent、论文、代码项目等，手机端自适应。
- `hub/research.py`：跨来源的关键词专题只比较**相同主分类**的内容，并排除将“论文”“代码仓库”当作技术主题的旧混编路径。
- `tests/test_categories.py`：区分 arXiv Agent 论文、GitHub Agent 项目、Agent 技术文章、教程/产品/科学，并验证分类独占及跨源不混编。
- `tests/discovery-ui.cjs`：验证独立分类导航和筛选，`tests/integration-browser.cjs`：真正 Chromium 分类筛选烟测。

## 兼容及边界

- 不变更 `items` 和 `personal` SQLite 表的已有数据与 ID，不迁移旧收藏、私有笔记或课程进度。
- 分类作为实时**可解释的展示推断**；错误分类目前保留“规则初判”提示，不冒充人工精确打标。未来可另行增加站主手工修订标签。
- 原 30+16 节课程和原始热点采集链路不修改；匿名访客仍只能看到原版公开精选与候选，分类页为站主功能。
- 本轮开发与测试在 GitHub Draft PR 中；云端真实运行版本仍为前期验收的 `32b126f`。备案申请已发起，但官方通过尚未核实；未上线新的正式域名、DNS 或证书。
