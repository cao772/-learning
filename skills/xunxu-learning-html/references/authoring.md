# 内容与实现指南

## 从资料走向课程

先确定读者学完应能解释或完成的事情，再挑资料。多篇新闻围绕同一原理时合并讲解，避免把新闻列表简单换成课程列表。让前后单元有真实依赖关系，解释上一课的问题如何引出下一课；没有关系就允许独立学习，不强行串联。

聚合站用于发现题目。涉及技术解释，优先读原作者、官方文档与论文。标明资料快照时间和内容修订时间，不能因修改样式就把旧消息变为“今天最新”。无法打开或核实的内容不能冒充已读全文。

来源支持具体主张；不要将厂商某个硬件、数据集或并发条件下的性能当作普遍结论。独立编写教学场景和算例，明确其假设，遵守来源的引用与摘要限制。

## 什么叫讲清楚

以一个连续问题推进：原本怎样做 → 遇到什么障碍 → 新方法改变哪一部分 → 每一步如何产生结果 → 代价与失效条件。段落数量由这个推理链决定，不预设“三点”或固定 4–7 点。

每引入一个术语，先说明它是什么、在当前问题中做什么，再解释容易混淆的边界；不要从连续的“不是……”“不等于……”开始。名称的英文、直译或由来只在有助理解且可核实时补充，不编造词源。需要数学时先定义符号和单位，再代入小数字，最后解释计算结果。

展开旧提纲只是呈现调整。重写讲解时，还要检查相邻段落能否回答“上一步得到了什么，为什么现在需要这一步”。主线中的缺口应补上；并列知识应明确作为比较或补充。新增段数、字数和默认展开都不能单独证明讲透。

贯穿例子保持对象、符号、单位和前提一致。换到更一般的情况时，明确哪些条件变了、哪些结论仍成立。例如两项固定分布的采样算例，不能不加说明地跳到分布随前缀变化的多词生成；玩具递推也不能直接推出真实架构的性能。

讲完一个机制后，让读者先预测改变一个条件会发生什么，再用算例或实验检查，并解释一个看似合理但会失败的做法。随后可减少提示，给一个新场景检验迁移。按主题选用，不为每课强凑同样数量的练习。

交互应服务于具体理解问题：说明变量如何影响结果、哪些控件彼此独立，以及当前显示的是一次路径、期望值还是实际测量。随机机制的手动分支演示不冒充随机抽样；只显示速度曲线也不能替代对概率校正过程的解释。

值得保留的教学方法：

- **概率校正**：不仅说“草稿交给大模型验证”，还用一个两选项分布演算接受质量、拒绝残差与最终概率。对比错误校正会产生什么偏差。
- **缓存**：区分省去历史表示重算与仍需读取历史；从单层、单 token 的元素数推到整条序列内存，再讨论并发。
- **压缩状态**：给出不同历史得到同一玩具状态的反例，解释信息压缩的代价；明确玩具递推不是实际架构的完整模型。
- **系统优化**：先测总耗时的组成，再算局部提速的整体上限；把协调、重试和验证成本算进去。

以上是讲法示例，不要求每套新课程教授这些主题。

## 页面与交互

参考 assets/reference.html 的视觉与交互，但按新课程的数据组织生成：

- 桌面侧栏放分组目录与进度，正文保留舒适行宽。手机侧栏折叠，标题与标签不挤出屏幕，按钮可点击。
- 首页给出学习目标、完整路线和可选短路线。学习时长是估计，不能用未经测量的数字保证学习效果。
- 正文依次讲解；补充术语与答案可折叠。每课可保留笔记和上一页/下一页。
- 实验应展示输入、假设、计算或判定规则以及结果。参数变化要真正改变结果，避免假交互。重置恢复明确的初值。
- 自测选项体现常见误解，反馈说明原因。通过一道题不宣称掌握整个主题。
- 保留来源入口、键盘焦点与标签语义。若有搜索和弹窗，检查无结果、关闭、焦点恢复和手机操作。
- 用户笔记按普通文本处理，动态文字插入时转义；不使用用户文字拼接可执行脚本。

独立 HTML 内嵌样式和脚本，优先系统字体。默认不使用 CDN、远程字体、运行时 fetch 或后端。外部链接标明需要联网。页面内的模拟不得伪装成真实模型调用或真实外部操作。

存储不可用时仍能阅读和交互，并提示通过导出保存笔记。同一课程修订保留稳定 lesson ID、路由和兼容存储；新课程更换存储命名空间，避免进度与笔记串用。分组、总数、最后一课和进度分母来自数据。

参考实例包含特定的 16 课、五阶段路由和三段晨读，不可只换标题就作为新的课程交付。参考内已有功能可以复用，但所有可见内容、计数、专用实验与来源都要对应新主题。无需把本机原项目路径写进新产物。

## 与改动匹配的验证

内容：核对推理前提、计算、单位、反例和来源。检查是否有只有定义没有过程的段落，是否遗漏了让读者理解所需的一步。

页面：用浏览器查看桌面与手机实际显示。大量共用布局可批量检查溢出，长公式、长标题或特殊交互需要单独看。不能仅靠 HTML 能生成就宣布页面正常。

功能：覆盖实际交付的导航、实验、答案反馈、笔记刷新恢复与导出。已有课程的小修改只补验受影响部分，不必机械重跑全部历史测试。

离线：检查有无外部脚本、样式、字体或运行时网络依赖。有条件时断网验证本地交互。若仅通过 HTTP 自动化验证，明确没有据此保证所有浏览器的 file: 存储行为。

Skill 自身：检查 frontmatter、资源链接、正向触发场景与误触发边界。没有实际调用评测就只报告静态审阅和实际产物检查。

## 已获授权后的多处同步

维护已有个人 Skill 时先更新原版本，再将确认过的差异同步到仓库分发副本；先比较双方内容，保留各自的新改动。课程成品、Skill 参考实例和规则文档分别核对，不因参考实例存在就把旧课程写回当前源码。

同步 GitHub 前获取远端状态，审阅实际差异，采用普通推送；远端新增提交时先整合，不强推覆盖。同步 Notion 前读取现有页面，定点修改对应段落和版本链接，保留其他人的笔记、子页和附件；同一内容已存在就更新，不重复建页。相对资源链接在 Notion 中换成可访问的仓库链接。交付记录绑定已确认的提交，区分本次验证与历史验证；跨平台部分失败时明确报告未完成项。
