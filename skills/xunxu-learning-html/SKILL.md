# 循序学习 HTML

把知识整理成能读懂、能操作、能复述的学习页面。沿用暖白与深绿、侧栏目录和安静的阅读排版；内容深度优先于卡片数量和形式整齐。

## 资源

- [完整参考页面](assets/reference.html)：可直接离线打开。展示真实排版、导航、实验、自测、笔记与响应式行为，也可提取其中的 CSS 和通用交互代码。
- [内容与实现指南](references/authoring.md)：讲解结构、研究方法、实现约束和验证要点。

参考页面是一个历史课程实例，不是实时资讯，也不是要求照搬的默认课程。生成新课程时替换主题、资料、日期、例子、实验、标题及内容标识；不能保留不相关的来源或硬编码的课数。

## 工作方式

从用户材料和已有页面推断主题、基础与需要的深度。有明确参考设计就直接复用；用户未指定课数、标题或细节时自行组织。先检查现有产物，保留用户认可的内容与功能。

将阅读线索转为连贯的学习路线：前置知识 → 真实问题 → 原理 → 应用与局限。网站是选题入口；涉及最新能力或技术细节时回到官方文档、论文或作者原文核对。明确区分事实、教学假设和推断，保留可点击来源。

默认交付一个能直接打开的独立 HTML。仅在已有工程需要或维护确实受益时保存数据与构建源码。无需用户安装框架、提供 API Key 或启动后端；发布上线须有相应授权。

## 学习体验

较完整的单元可沿用五个阶段：

1. **认识问题**：用具体场景说明要解决什么、为什么值得学、需要哪些前置知识。
2. **一步步理解**：围绕同一问题展开因果过程。关键推理直接可读，段数随主题变化。
3. **例子细讲**：从输入到结果走完一个案例，解释每一步为何如此，并留一个迁移问题。
4. **动手实验**：用滑块、选项、情景或可观察演示验证直觉。先预测，再操作，再解释结果。
5. **检查理解**：考查关键区别或迁移能力，反馈解释错误原因，最后引导用户用自己的话复述。

这五个阶段是默认导航，不是每个题目都必须填满的模板。短主题可以合并；不适合交互的主题不硬造数值实验。课数、讲解段数、例题步骤和选项数量按内容决定。

### 已确认的偏好

- 不把正文固定成“三点式”“三个概念”。简洁放在标题和导航上，不删掉理解机制所必需的中间过程。
- 理解当前段落必需的定义和关键推理默认展开；先说明“它是什么、用来做什么”，再讲边界。词源或命名缘由在确有帮助且能核实时补充。延伸术语、补充边界和参考答案可折叠，不能把理解门槛藏起来。
- **不添加“本课的信息路径 / 概念示意”模块**，也不换名字放回由几个词和箭头组成的装饰性流程条。真正能解释机制的图、数值过程或状态变化仍可按需使用。
- 保留原设计的留白、字号层级、暖白与深绿。避免把正文切成大量等高卡片，也不增加无助理解的动画。
- 让读者能够回答“为什么、怎样发生、什么时候不成立”，不能只记住术语和结论。

## 实现与验收

按需读取 authoring.md。参考页面中的旧课数、分组索引、晨读路线、课程日期及专用实验属于示例数据，不能当作通用框架常量。新页面的计数与进度应来自实际数据；不同课程使用独立存储键，修订同一课程则保持兼容。

验证真实显示和核心行为：桌面与窄屏无页面横向溢出；导航、实验、自测反馈、笔记保存和导出按交付范围可用；数值例子符合题设；来源与主张对应。正文与本地交互不依赖网络。引用外部资料的链接可联网打开。

交付时给出 HTML 入口，简短说明内容、验证范围与真实限制。对普通更新不额外要求审批、访谈或安装；不把静态格式检查说成独立行为评测。
